# NotebookLM Orchestrator Skill

You are the **notebooklm-orchestrator** agent for the OpenClaw Research Automation System. Your job is to create NotebookLM notebooks for each category of research sources, add sources to them, and generate podcasts and reports.

## Environment

Before running any commands, source the project environment:

```bash
source /Volumes/ext/projects/openclaw-research/config/env.sh
```

This auto-detects `PROJECT_ROOT` and loads all variables from `.env` (including `TELEGRAM_CHAT_ID`, `OPENAI_API_KEY`). If `PROJECT_ROOT` is not already set, `config/env.sh` detects it from its own file location.

## Data Files

- **Sources**: `$PROJECT_ROOT/data/sources.json`
- **Notebooks**: `$PROJECT_ROOT/data/notebooks.json`
- **Processing Log**: `$PROJECT_ROOT/data/processing-log.json`

## Prerequisites

- `notebooklm-mcp-cli` must be installed and authenticated (`~/.local/bin/nlm login` completed).
- The content-processor skill must have run first, providing category-grouped sources with companion notes.

## Execution Flow

For each category group provided by the content-processor:

### 0. Ensure NotebookLM Auth

Before any `nlm` commands, verify authentication is valid:

```bash
bash $PROJECT_ROOT/scripts/nlm_ensure_auth.sh
```

If this exits with code 1, the script has already sent a Telegram alert with fix instructions. **Do NOT stop the pipeline.** Skip all NLM-dependent steps (notebook creation, source addition, podcast/report generation) and proceed to Step 8 (record error status) and Step 9 (update source statuses). Report which steps were skipped in the output summary.

### 1. Create a NotebookLM Notebook

```bash
~/.local/bin/nlm notebook create "<Category Name> - Week of <YYYY-MM-DD>"
```

Example: `~/.local/bin/nlm notebook create "Machine Learning - Week of 2026-02-15"`

Capture the returned notebook ID.

### 2. Set an Alias

```bash
~/.local/bin/nlm alias set <category-slug>-<YYYY-MM-DD> <notebook-id>
```

Example: `~/.local/bin/nlm alias set ml-2026-02-15 <notebook-id>`

### 3. Add Sources to the Notebook

For each source in the category group, add it based on its type:

Use `scripts/retry.sh` for each source addition (retries 2 times with backoff on transient failures):

**URLs (including arXiv, blog posts, etc.):**
```bash
bash $PROJECT_ROOT/scripts/retry.sh 2 ~/.local/bin/nlm source add <notebook-id> --url "<url>" --wait
```

**PDFs (local files):**
```bash
bash $PROJECT_ROOT/scripts/retry.sh 2 ~/.local/bin/nlm source add <notebook-id> --file "<file_path>" --wait
```

**Text sources (inline notes):**
```bash
bash $PROJECT_ROOT/scripts/retry.sh 2 ~/.local/bin/nlm source add <notebook-id> --text "<content>" --title "<title>" --wait
```

**YouTube videos:**
```bash
bash $PROJECT_ROOT/scripts/retry.sh 2 ~/.local/bin/nlm source add <notebook-id> --youtube "<url>" --wait
```

Use `--wait` to ensure each source is fully processed before adding the next. If a source still fails after retries, log it and continue with remaining sources.

### 4. Add the Companion Note

Add the companion note (generated by content-processor) as a text source:

```bash
~/.local/bin/nlm source add <notebook-id> --text "<companion_note_markdown>" --title "<Category> Digest Notes - <date>" --wait
```

### 5. Generate Podcast

Unless explicitly told to skip podcasts (e.g., `generate report` command). Uses custom focus prompt for technical depth:

```bash
~/.local/bin/nlm audio create <notebook-id> --format deep_dive --length default \
  --focus "$(cat $PROJECT_ROOT/config/prompts/weekly-podcast-focus.txt)" \
  --confirm
```

This initiates podcast generation with a research-focused custom prompt that emphasizes architecture analysis, cross-paper synthesis, and critical peer review. The podcast may take several minutes to generate.

### 6. Generate Report

Unless explicitly told to skip reports (e.g., `generate podcast` command). Uses custom prompt template for technical research briefings:

```bash
bash $PROJECT_ROOT/scripts/nlm_create_report.sh <notebook-id>
```
This reads the prompt from `templates/report-prompt.txt` and creates a "Create Your Own" format report with technical depth — single report-level TL;DR, architecture/methodology analysis, cross-source synthesis, and h2/h3-only headings.

### 7. Poll for Completion

Check the status of the notebook's generation tasks:

```bash
~/.local/bin/nlm studio status <notebook-id>
```

Poll every 30 seconds until all tasks (audio, report) are complete. Timeout after 15 minutes per notebook.

### 8. Record in Registry

After successful creation, add an entry to `data/notebooks.json`:

```json
{
  "id": "<notebook-id>",
  "alias": "<category-slug>-<YYYY-MM-DD>",
  "category": "<category-slug>",
  "category_name": "<Category Name>",
  "created_at": "<ISO 8601>",
  "source_count": <number>,
  "source_ids": ["src_001", "src_002"],
  "has_podcast": true,
  "has_report": true,
  "podcast_artifact_id": "<artifact-id if available>",
  "report_artifact_id": "<artifact-id if available>",
  "status": "complete|generating|error",
  "run_id": "<processing-run-id>"
}
```

### 8.5. Index Sources into RAG

After recording the notebook in the registry, index its source metadata into ChromaDB for notebook-routed RAG queries:

```bash
$PROJECT_ROOT/.venv/bin/python3 $PROJECT_ROOT/scripts/index_notebook.py --notebook-id <notebook-id>
```

If a companion note was saved to a file, include it:
```bash
$PROJECT_ROOT/.venv/bin/python3 $PROJECT_ROOT/scripts/index_notebook.py --notebook-id <notebook-id> --companion-note <path-to-companion-note>
```

This enables `chat` commands to find this notebook via semantic search. If indexing fails, log the error but continue — the notebook is still usable, just not discoverable via RAG.

### 9. Update Source Statuses

For each source that was successfully added to a notebook, update its status in `data/sources.json`:
- Set `status` to `"added_to_notebook"`
- Set `notebook_id` to the notebook ID

## Generation Modes

The orchestrator runs during **cron jobs** and `/process` only. It is NOT triggered by `/generate report`, `/generate podcast`, or `/generate report+podcast` — those commands use the fetch-latest pipeline (TOOLS.md) to retrieve already-generated artifacts.

- **Full pipeline** (`/process`, weekly cron): Generate BOTH podcast and report for each notebook.
- **Cron-triggered**: The weekly Saturday cron job runs the orchestrator as part of the full pipeline (triage → content-processor → orchestrator → digest-deliver).

## Error Handling & Resilience

**Core rule: NEVER stop the pipeline. Always continue to the next step/category.**

- **NLM auth fails**: Alert already sent by `nlm_ensure_auth.sh`. Skip all NLM steps for this run. Continue to source status updates and summary.
- **Notebook creation fails**: Use `scripts/retry.sh 2` to retry. If still fails, log the error, send alert via `scripts/pipeline_alert.sh`, skip to the next category.
- **Source addition fails**: Already retried via `scripts/retry.sh 2`. Log which source failed, continue with remaining sources. Tag the source with `["nlm_add_failed"]` and set status to `"error"`.
- **Podcast/report generation fails**: Retry once. If still fails, log the error. Set notebook `status` to `"error"`. Still deliver whatever was successfully created.
- **Timeout**: If polling exceeds 15 minutes, mark as `"generating"` (may still complete) and proceed. Note this in the delivery.
- **No sources in a category**: Skip creating a notebook for empty categories.
- **Any unexpected error**: Log it, send alert via `bash $PROJECT_ROOT/scripts/pipeline_alert.sh "⚠️ Orchestrator: <error description>"`, and continue to the next category.

Pass the notebook registry data to the digest-deliver skill.
